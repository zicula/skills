# Onboarding Kit

The first-30-days client operating system for freelancers and agencies —
run the same loop for every new client, from the "yes" to the handoff.
About 45 minutes of onboarding work per client and 5–10 minutes a week
after that. Extracted from the full Client Onboarding Kit (same files,
same process).

## When to use

The user mentions any of: a new client just said yes and onboarding needs
to start; preparing or running a kickoff call; writing a kickoff recap;
aligning scope or handling a "can you also just…" change request; planning
project milestones; collecting logins and assets without asking for raw
passwords; sending welcome packets or weekly status updates; pushing back
on scope creep; closing out and handing off a project; client intake
questionnaires, onboarding checklists, or an agency delivery rhythm.

## How to use this skill

1. **Start from the map.** Read `references/START-HERE.md` — the 8-step
   loop (CAPTURE → MEET → ALIGN → CONNECT → PLAN → SET RHYTHM → WORK →
   CLOSE), the time budgets, and the worked example. All paths are relative
   to `references/`.
2. **Set up once (about 90 minutes).** Copy the kit folder as the working
   copy, fill the `[bracketed]` blanks in the templates with the user's own
   details (company name, response times, tool names), and delete rows or
   questions that do not apply. That setup is shared by every future client.
3. **Run the loop per client (about 45 minutes + the call).** Send
   `1-intake/new-client-intake-questionnaire.md` before kickoff and log
   answers in the CSV; mark each answer green/amber/red as it arrives (a
   red becomes a kickoff agenda item before anything is signed). Meet with
   `2-kickoff/` agenda + script, send the recap within 24 hours, align
   scope with `3-scope/scope-alignment-worksheet.md`, connect access with
   `4-access-assets/`, plan milestones, and send the welcome packet in week
   one.
4. **Work the rhythm.** Send the 5-line status update every Friday from
   `5-communication/status-update-template.md`; when the client asks for
   extras, use one of the four read-aloud scripts in
   `5-communication/scope-creep-scripts.md` and log real changes through
   `3-scope/change-request-form.md`.
5. **Close the project.** Final week, run all three checklists in
   `6-handoff/` — deliverables and walkthrough, offboarding survey, then
   archive with the data-hygiene checklist (rotate and purge at handoff).
6. **Draft with AI, guarded.** For any writing step, use the 8 prompts in
   `7-ai/ai-prompt-pack.md` — they forbid invented facts and ambiguous
   notes get flagged `[CHECK]`; the fact-check gate at the bottom of that
   file is mandatory and the final check stays with the user.
7. **Respect the two rules that make the kit work.** Nothing starts before
   CAPTURE and ALIGN are done, and if it is not written, it is not included
   (a process rule for internal alignment — it does not replace the
   contract; see `references/10-scope-and-disclaimers.md`).

## Honest limits

Plain process documents, not software — no app, no CRM integration, no
automation. Not a contract; real agreements belong to the user's lawyer
(the kit deliberately contains no contract templates). Nothing about
employment law, taxes, or regulated advice. Access is collected as
platform-based invites, not raw credentials, and templates hold the
smallest amount of client data needed — storage beyond that is the user's
own policy. All names, companies and figures in the examples are invented
for illustration.
