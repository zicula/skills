# Milestone Plan Template

**Step 6 of the loop — PLAN.** The milestone plan turns the aligned scope
into dated checkpoints. It is deliberately coarse: milestones, not tasks.
You keep your own task list; the client sees this.

Rules:
- Work backwards from the hard deadline (intake question 36), forwards from
  today, and make them meet honestly.
- Every milestone has: what exists when it's done, who approves, and what
  input the client owes **before** it starts — the input dates are the ones
  clients forget, so they get their own column.
- Dates move only through change requests or written schedule notes — both
  announced in the Friday update.

---

## The template

```
PROJECT: ____________  CLIENT: ____________
HARD DEADLINE: ____________  (what happens if it slips: ____________)
PLAN VERSION: v1 — dated ____________
```

| # | Milestone | Done means | Client input owed before | Input by | Approver | Target date |
|---|---|---|---|---|---|---|
| M1 | | | | | | |
| M2 | | | | | | |
| M3 | | | | | | |
| M4 | | | | | | |

Buffer note (write yours here): [e.g. "one week of slack between last
milestone and hard deadline — held by me, announced if it gets spent"]

## Worked example (Fieldnote × Copperline)

HARD DEADLINE: Nov 1 soft launch (slips = misses wholesale season)
Plan v1 — 2026-10-08

| # | Milestone | Done means | Client input owed before | Input by | Approver | Target date |
|---|---|---|---|---|---|---|
| M1 | Brand direction locked | 2 directions presented, 1 chosen in writing | brand PDF + 3 liked/disliked references | Oct 7 | Dana | Oct 16 |
| M2 | Brand kit approved | final logo, palette, type, one-page guide | one feedback wave, single document | Oct 20 | Dana | Oct 27 |
| M3 | Site pages in review | 6 pages in staging, real copy, real photos | photo originals, final wholesale copy | Oct 14 | Dana + Riley | Nov 3* |
| M4 | Soft launch | live on domain, analytics + newsletter verified | Shopify admin invite (done Oct 9), launch checklist sign-off | — | Dana | Nov 1 |

*One week of buffer sits between M3 review and Nov 1 — held by Fieldnote,
spent only by written note.

### How the plan answered two real moments

- **Oct 12 — photos arrive late (Oct 14).** Input column shows photos were
  due Oct 14 and arrived Oct 14 18:00 — inside the day, M3 unaffected. No
  conversation needed because the date was written twice (here + recap).
- **Oct 20 — CR-001 (events page) approved.** The page reuses the shop
  template, so M3 "done means" gains "…+ events page (CR-001)" and the
  buffer absorbs the work. Friday update Oct 24 says exactly that. The plan
  is versioned: v1.1, dated 2026-10-24.

## Milestone hygiene (5 minutes, every Friday)

1. Open milestones.csv, glance at the next milestone's input column — if an
   input is missing and its date is inside 5 business days, name it in the
   Friday update under "decisions needed".
2. If a date moved, the CSV shows the old date struck through and a note
   with the reason (CR number or written schedule note).
3. Check the buffer: still there, or spent? Say which, in the update.

## What success looks like

- The client can name the next milestone and what they owe before it —
  because the Friday update repeats it.
- Dates have moved twice at most across the project, each with a written
  reason, and the client saw every move in advance.
- The hard deadline arrives with the buffer unspent or visibly accounted for.
