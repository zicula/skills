# Client Archive Checklist

The archive is for the person you cannot predict: future-you, a new teammate,
or the client who calls back in fourteen months asking "what was that font?"
Thirty minutes at project close buys that back instantly.

Rules:
- Archive once, at handoff — not "later", not during the support window.
- The archive must be understandable without you: folder names, a README, and
  dates do the explaining.
- Keep client data only as long as your stated policy says; the deletion
  step is part of the checklist, not an afterthought.

---

## The checklist

### 1. The folder (one project = one folder, dated)

```
2026-copperline-coffee-roasters/
├── 00-README.txt            (10 lines: project, dates, people, where things are)
├── 01-admin/                (proposal, scope worksheet, CR log, final milestones)
├── 02-communication/        (exported Friday updates thread, key decisions)
├── 03-deliverables-final/   (what the client received, frozen versions)
├── 04-source/               (editable/source files)
├── 05-access-record/        (systems list + who holds what now — no secrets)
└── 06-handoff/              (walkthrough recording, run book, survey answer)
```

- [ ] 00-README.txt written (see the 10-line format below)
- [ ] Final versions frozen — the archive holds what shipped, not drafts
- [ ] Access record lists systems + current holder (e.g. "Shopify — Dana
      Whitfield, owner") with **no** credentials in the file

### The 10-line README format

```
PROJECT:   Brand refresh + 6-page website
CLIENT:    Copperline Coffee Roasters (Dana Whitfield; approvals: Dana, Riley)
DATES:     Kickoff 2026-10-06 → handoff 2026-11-04
SCOPE:     In: brand kit, 6 pages, events page (CR-001), analytics+newsletter
           Out (decided): email templates, packaging, price-list automation
STATUS:    Live 2026-11-01. Support window to 2026-11-18, then ad hoc.
WHERE:     Final files 03/, sources 04/, live site admin — Dana
LESSON:    Input flags now go out with calendar invites (survey #2, v1.1)
CONTACT:   Reopen via [email] — reference "2026-copperline"
```

### 2. The snapshot

- [ ] Live-site/export snapshot stored if the project touches anything live
      (so a future "what changed?" has a baseline)
- [ ] Analytics/newsletter configs documented in one screenshot page each

### 3. The relationships

- [ ] Client + stakeholders filed in your relationship notes (who decides,
      who advises, what they care about — one line each)
- [ ] Follow-up date set: [e.g. +90 days, one-line check-in; +1 year,
      anniversary note] — two dates in your calendar now
- [ ] Referral/partner notes from the survey, if any (worked example: the two
      roasters Dana mentioned)

### 4. Data hygiene (your stated policy, executed)

- [ ] Client data reviewed against your retention policy: what stays (working
      docs, deliverables, invoices) and what goes (anything the client would
      not want stored: credentials that were shared, sensitive answers from
      the intake that no longer serve a purpose)
- [ ] Credentials: confirm all rotated at handoff; nothing stored in plain
      text anywhere (the access record lists holders, not secrets)
- [ ] Backups verified restorable — an archive you cannot restore is a mood,
      not an archive

### 5. The 5-minute test

- [ ] Hand the folder to a teammate and ask: "what was this project, how did
      it end, and where are the final files?" If they answer in under two
      minutes, the archive passes.

## What success looks like

- The callback in month fourteen takes five minutes, not an archaeology
  session.
- A new teammate reads the README and understands the project's shape without
  asking you anything.
- You hold exactly what your policy says you hold — and can say so, in
  writing, if a client asks.
